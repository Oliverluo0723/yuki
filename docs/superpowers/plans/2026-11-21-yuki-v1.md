# Yuki v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出一個手機網頁作品：手機直立時看到有遠近的落雪，平放時雪落在玻璃上化掉；有「常雪」和「北海道實際天氣」兩個模式；電腦上用滑鼠表達同一件事。

**Architecture:** 三種輸入（感測器、滑鼠、觸控）翻譯成同一份 `Pose`；兩個模式翻譯成同一份 `SnowConditions`。雪的狀態（`snow/`）只讀這兩份資料，不知道來源。p5 只負責把雪的狀態畫出來；感測器、權限、天氣、螢幕常亮都用瀏覽器原生介面。所有規則是純函式或不碰 DOM 的類別，用 Vitest 測；畫面與手感在裝置上手動確認。

**Tech Stack:** Vite 8、pnpm 11、TypeScript 5.9（strict）、p5.js 2.x（instance mode、2D 畫布）、lil-gui、Biome、Vitest、`@vitejs/plugin-basic-ssl`、GitHub Actions → GitHub Pages。

**Spec:** `docs/superpowers/specs/2026-11-21-yuki-design.md`（執行者兩份都要讀）

## Global Constraints

- 靜態網站，沒有後端，沒有金鑰。
- 看得見的雪都由 p5 畫（含 `p5.Graphics`）。感測器、權限、天氣、觸控、螢幕常亮不透過 p5。
- `pixelDensity` 上限 2。
- 目標 60 fps，最低 30 fps；雪片數量依幀率自動增減。
- 實際模式絕不顯示模擬的雪：`amount` 只能來自天氣資料；抓不到且沒有一小時內的舊資料時 `amount = 0`。
- 畫面上唯一的常駐介面是右下角一行小字。
- 介面文字用繁體中文。
- 第一版沒有聲音、鏡頭、匯出、積雪、指南針、觀眾用的設定面板。
- 每一格的 `dt` 一律先經過 `clampDt`（上限 1/15 秒）。
- **不要推送到任何遠端，不要建立 GitHub repo。** 只在本機 commit。
- 依賴版本：`p5 ^2.3.4`、`lil-gui ^0.21.0`、`vite ^8.3.6`、`vitest ^5.1.0`、`typescript ^5.9.3`、`@biomejs/biome ^2.6.6`；CI 用 pnpm 11.24.0、Node 24。
- 文件裡的數值都是起始值；凡是標「可調」的都要進開發面板。

## Review Focus

規格沒有明說、但真的會遇到的五種情況。每一條的測試都已經放進負責的任務裡。

1. **感測器事件帶著 `null`**（桌面 Chrome 會發一次 `beta: null` 的事件）：要當作沒有感測器、改用滑鼠，不能算出 `NaN` 的雪。→ Task 1 `readAngles`
2. **分頁切到背景再回來，`dt` 變成好幾秒**：雪不能瞬間移動、拉出橫跨螢幕的線、或一次落下一大批。→ Task 5 `clampDt`
3. **天氣服務回 200 但內容不是預期的形狀**（`{"error":true,"reason":…}`、長度不對的陣列、不是物件）：當作抓取失敗，不能當機。→ Task 3 `parseResponse`
4. **抓天氣還沒回來就切換模式、或連續切換**：晚到的舊回應不能蓋掉新的狀態。→ Task 4 `LiveWeather`
5. **手機旋轉或視窗變小時，玻璃上已經有雪**：落在新範圍外的雪要直接移除，不能卡在看不見的地方佔名額。→ Task 6 `Landings.step`

// 螢幕與水平面的夾角 e = acos(min(1, |g.z|))，換成度

- [ ] **Step 3: 實作三個可測的模組**

- `wheel`：`posture += pixels / 600`，夾在 0–1。`moveX`：`lean = clamp((x / width − 0.5) · 2, −1, 1)`。`pointerPose`：`down = (sin(lean · 35°), cos(lean · 35°))`。
- `PointerSource`：在 `target` 上聽 `wheel`（`{ passive: false }`，`preventDefault()`）和 `pointermove`（只處理 `pointerType === 'mouse'`）。
- `WarmTracker`：放開後 `heat` 每秒減 `1 / 1.5`，到 0 移除。
- `attachWarm`：`pointerdown`／`pointermove`／`pointerup`／`pointercancel` 對應 `down`／`move`／`up`，用 `pointerId`。滑鼠不用按下：`pointermove` 且 `pointerType === 'mouse'` 時，id 固定 `-1`，第一次出現當作 `down`，`pointerleave` 當作 `up`。

- [ ] **Step 4: 實作兩個瀏覽器模組（不寫單元測試）**

- `requestOrientation`：`DeviceOrientationEvent` 不存在 → `'unsupported'`；有 `requestPermission` → `try { await } catch → 'denied'`，結果不是 `'granted'` 也回 `'denied'`；否則 `'granted'`。
- `OrientationSource.start`：聽 `deviceorientation`，每個事件經 `readAngles`，是 `null` 就丟掉，否則存成最新的目標重力。`step(dt)`：用 `smoothGravity` 追目標。`current(uprightDeg, flatDeg)`：還沒收過有效事件回 `null`；否則先把平滑後的重力正規化，再用 `postureFromGravity`（帶入兩個角度）和 `downFromGravity`（`screenAngleDeg` 取 `screen.orientation?.angle ?? 0`，`last` 是上一次回傳的 `down`，起始 `(0, 1)`）。規格提到可參考 One Stroke 的 One Euro 濾波；這裡先用指數平滑，手機上覺得抖或拖再換。
- `keepAwake`：`navigator.wakeLock` 不存在就什麼都不做；否則 `request('screen')`（包在 `try/catch`），並在 `visibilitychange` 回到 `visible` 時重新請求。

```ts
snowing  = snowfall > 0 || [71, 73, 75, 77, 85, 86].includes(code)
floor    = { 71: 0.15, 77: 0.15, 85: 0.15, 73: 0.5, 75: 0.8, 86: 0.8 }[code] ?? 0
fromCm   = 0.15 + 0.85 * sqrt(min(snowfall, 1))
amount   = snowing ? max(fromCm, floor) : 0
ew       = −sin(windDirection) * windSpeed        // km/h，正值往東（畫面右）
angle    = min(70°, |ew| * 45° / 20)
windX    = sign(ew) * tan(angle)
gust     = clamp((windGusts − windSpeed) / 30, 0, 1)
wetness  = temperature === null ? 0.5 : clamp((temperature + 5) / 5, 0, 1)
```
